## Rationale and boundary

The prerequisite contains the scheduler correctness mechanism needed by the
existing factor-2 path and the reproduced P1:

- `ProjectedSourceAccess` retains exact raw producer and consumer `MemoryDep`
  pairs for `INTERLEAVED` and `BROADCAST` projections.
- Broadcast planning collects all same-name reads before requiring `MemoryDep`,
  so `StarDep` or `WeakDep` cannot be silently omitted from the proof.
- `broadcast_source_names` is derived from those records.
- The staged plan carries exact pairs through initial planning and append
  replanning. New sub-parent edges must use those exact pairs. The inherited
  #190594 parent-to-grouped relation retains its existing equivalence proof,
  but only for reads owned by the grouped stage; sub-parent ownership takes
  precedence and cannot fall through to that legacy path.
- Planner-approved mismatches remain fail-closed for ambiguous multiwrites,
  temporary/indirect indices, and synchronization-requiring atomic writes.
- Fusion legality validates the raw `X | R` boundary of multidimensional
  interleaved accesses before normalization can erase it. One-active-axis
  accesses remain valid because all other loop axes are broadcast-invariant;
  indirect accesses reject.
- `_can_fuse` retains a `StagedReductionPlan` only after branch-local
  recognition. A recognizable sub-parent candidate whose plan fails rejects;
  an unrelated pair continues through ordinary fusion.
- An empty dependency-match tuple still belongs to a valid staged plan. It uses
  generic read/write scoring and prevents later loop rewrites.
- Append legality is followed by a fresh plan before mutation/fusion.
- The dead name-based `allow_index_equivalence` API is removed in this layer.
- Shifted parent-output, shifted reduced-source, and both transposed-frame P1
  regressions live in this layer.

The upper layer contains the MXFP6-specific extension:

- factor-4 and `IDENTITY` projection planning;
- multi-output lane grouping and the associated SIMDScheduling/Triton codegen;
- MXFP6 packing and preshuffled coverage.

The upper projection record does not store a per-consumer lane. Production only
needs the raw consumer dependency; the planner proves a concrete lane locally
before recording it. The standalone cpp_wrapper test is removed per review,
and the unrelated `can_fuse` mutation-tracker `try/finally` change is absent.
